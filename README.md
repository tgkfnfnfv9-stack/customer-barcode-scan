# お客様用 バーコードスキャン｜株式会社小林機械

機械の銘板バーコードを Android／iPhone で読み取り、写真・機械情報・公開価格・仕様を画面内に表示するお客様向けツールです。
ログインは不要。読み取りエンジンは端末内で動き、機械情報の取得にはネット接続が必要です。単一の `index.html` だけで動きます。

**公開URL：** https://tgkfnfnfv9-stack.github.io/customer-barcode-scan/

---

## 使い方

1. 上記URLを Android の Chrome または iPhone の Safari で開く（ホーム画面に追加すると便利）
2. 画面下の「スキャン」を押し、カメラの使用を許可する
3. バーコード全体を枠に合わせると自動で読み取る。読み取り成功でカメラが閉じ、履歴へ登録して一覧に戻る（最新が一番上）
4. 次の機械を読むときは、もう一度「スキャン」を押す
5. 読み取り履歴に写真・機械名・メーカー・型式・年式・公開価格が表示される。仕様は「仕様を見る」で開く

撮影ボタンの操作は不要です。読み取れない場合は、カメラを開いたまま再試行します。
カメラを閉じるか画面を離れると停止します。「アルバムから選ぶ」と番号の直接入力も使用できます。
連続スキャンにはHTTPSと対応ブラウザが必要です。

### 主な機能

- 読み取り履歴が積み上がる（同じコードは重複せず先頭へ移動）
- 各コードから公開情報を取得して表示（公開価格が設定されていない機械は金額を灰色の `---` で表示）
- 取得に失敗したときは「再取得」で再試行できる（通信・本文の受信は15秒でタイムアウト）
- 「仕様を見る」の開閉や別の機械情報の取得で、閲覧中のカードの位置を保つ
- 写真を取得できないときは「写真なし」を表示
- カメラが使えないときは番号を直接入力して登録することも可能
- 個別コピー（各行）／すべてコピー（まとめて）／個別削除（✕）／すべてリセット
- 履歴は端末内に保存（閉じても更新しても残る）
- 写真解析中のリセットや画面離脱は解析を中止し、古い結果で履歴を復活させない

## 技術メモ

- 単一 HTML（CDN・ネット依存なし）。読み取りエンジンは ZXing-C++（WASM）を base64 で埋め込み
- 取得先：`https://www.kkmt.co.jp/staff/api/stocks/<コード>`（認証情報は送らない）
- 表示する金額はログインなしで返る `public_price` のみ。`price` や `current_price` などの社員価格・メモは使用しない
- 履歴に保存するのは番号と読み取り形式のみ。情報は起動時に再取得する
- 印字と符号化値が異なる機械は、`index.html` 内の `OVERRIDE_MAP` に登録して対応


### カメラの読み取り改善

- 操作は「スキャン」で開いてバーコードをかざすだけ。ズーム・ライト・カメラ切替は使用しない。
- 背面カメラを優先し、1920×1080・30fpsを希望する。縦持ちでも取得条件を入れ替えず、対応端末ではブラウザによる映像の切り抜き・引き伸ばしを避ける。実際の解像度は端末に依存し、未対応の場合は基本設定で起動する。
- 対応カメラでは連続オートフォーカスと自動露出を有効にする。連続AFが非対応、または設定が拒否された場合は、単発AFに対応していれば起動時に1回要求する。単発AFは他の調整後に行い、後続の設定で繰り返さない。
- ブラウザが `pointsOfInterest` を認識し、自動AFに対応する場合は、読み取り枠の中央を自動調整の対象として指定する。端末によっては指定が反映されない。設定に失敗したり応答が遅れたりしても、読み取りは続ける。
- TORQUEを含む機種ごとの対応状況はカメラAPIから判断する。写真から推測した型番やレンズ番号でカメラを切り替えない。
- 中央の帯は元の画素のまま解析し、細いバーが縮小で消えることを防ぐ。ガイドはこの解析範囲の内側に表示する。定期的に映像全体も解析する。
- 未加工の映像と、銘板の明暗に合わせて補正した映像を交互に解析する。明るい銘板の白飛び・暗い銘板の黒潰れを避け、補正は最大4倍に制限する。ほぼ無地の映像は増幅しない。
- 動画の解析画像は約120万画素までに抑える。中央の帯は幅3840pxまで等倍を保ち、全体解析は長辺1920pxまでに縮小する。
- 動画で読み取れない状態が続く場合、対応ブラウザでは `ImageCapture.takePhoto()` で静止画を内部取得し、アルバムと同じ画像解析を補助として行う。画面・ボタン・操作手順は変更しない。画像は端末内で処理する。
- 静止画補助はカメラ初期調整後、2秒以上かつ4回以上の映像読取失敗で開始する。フラッシュ無効に対応する場合だけ、必ず `fillLightMode:'off'` を指定する。撮影は1回のスキャンにつき最大3回、取得・解析は同時に1件までとし、完了後に1.5秒以上空ける。
- 静止画は長辺2560px以内を目安として要求する。実際の撮影サイズは端末に依存するため、JPEG/PNGの寸法を画像展開前に確認し、800万画素を超える画像は補助解析しない。静止画の設定・撮影に失敗した場合や、撮影が5秒以内に応答しなかった場合は、そのスキャン中の補助を停止して通常の動画読取を続ける。
- 静止画だけで登録する場合も、10秒以内の別々の撮影で同じ番号を確認する。同じ写真の切り抜きや明暗補正を2回分の確認として数えない。撮影中の一時的な映像停止に有限の猶予を設け、恒久的な停止の検知は維持する。
- 同じ番号を別の映像フレームで確認してから登録する。ぼやけるときはレンズを拭き、バーコード全体が枠に入る距離まで少し離して静止する。

### 開発時の確認

Node.js 18以降で `node --test tests/live-scan.test.cjs` を実行する。カメラの終了後の結果、履歴の検証、手入力、仕様開閉、通信とJSON本文のタイムアウト、古い応答の無視、コピーと写真解析の中止を確認する。

GitHub Actions は Chromium/WebKit でも仕様開閉と閲覧位置、社員情報・認証情報を使用しない公開表示、金額なし `---`、写真失敗、読み取りエンジン初期化失敗をテストデータで確認する。実API・実認証へ接続しない。ローカルでは `npm install --no-save --package-lock=false playwright@1.62.1`、`npx playwright install --with-deps chromium webkit`、`node --test tests/browser-layout.test.cjs tests/browser-camera.test.cjs` を実行する。

端末固有のカメラのピント・速度は実機で確認する。 静止画補助は動画と写真の取得経路の違いに対応するもので、標準カメラと同じレンズ・画質・合焦を保証しない。TORQUE G06のライブ映像での読取改善は実機での確認が必要。

カメラの回帰テストは、取得条件とピント設定の維持、未対応設定、権限拒否、終了後の非同期応答、一時的な映像停止、別フレーム確認を検証する。ブラウザでは生成した細いバー・薄い印字・軽いぼかしのあるバーコードを内蔵WASMで読み取り、変更前の画像処理では読めなかった条件も確認する。実際のレンズのピントや暗所性能は、模擬映像では検証できない。

実機では Android Chrome と iPhone Safari で、通常・暗所・反射する銘板、近距離／少し離した距離、縦横表示、閉じる／再開を確認する。
